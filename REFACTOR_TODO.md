### 1a. Fix Windows shell spawn  — `server/lib/toolRunner.ts`
- [ ] `startDetached()`: replace `spawn('cmd.exe', ...)` with absolute
      `process.env.ComSpec ?? 'C:\\Windows\\System32\\cmd.exe'`.

- [ ] Add module const `WIN_SHELL = process.env.ComSpec ?? 'C:\\Windows\\System32\\cmd.exe'`.

### 1b. Remove + block reserved-executable files in workspace
- [ ] Delete stray `agent-workspace/cmd.exe` (done during refactor; note it can be regenerated by a
      bad `>` redirect, hence the guard below).
- [ ] In `write_file` and `run_terminal` mkdir/redirect paths, reject creating a workspace file whose
      basename matches `/^(cmd|powershell|pwsh|bash|sh|node|npm|python|py)\.(exe|bat|cmd|ps1)$/i`.

### 1c. `cd <dir> && rest` handling — `run_terminal`
- [ ] Parse a leading `cd <dir>` segment; run the remainder with `cwd` set to the resolved subdir
      (must stay inside `WORKSPACE_DIR`, else path-traversal denied). Removes the `&&`-after-cd case
      that produced `spawn UNKNOWN`.

### 1d. Overwrite-guard relaxation (session-created files only) — `write_file`
- [ ] Add a per-session `Set<string>` registry of absolute paths created by `write_file`.
- [ ] On overwrite attempt: if path is in the session registry AND content differs → allow, with a
      one-line note nudging `edit_file` next time. If NOT in registry (pre-existing/user file) → keep
      the current block. Identical content → keep the existing no-op message.
- [ ] Registry keyed by `sessionId`; export a `clearSessionFileRegistry(sessionId)` used on reset.

### 1e. Duplicate-failure short-circuit — `runTool` / chat loop
- [ ] Track a hash of `name + JSON.stringify(args)` for each FAILED tool call per session.
- [ ] If the same failing call is re-issued, do NOT execute; return an escalated message
      ("identical call already failed — change approach") and count it as a consecutive failure so the
      existing pause@3 / kill@5 ladder engages.

### 1f. Persist assistant turn BEFORE executing tools — `server/routes/ollama.ts` chat loop
- [x] ALREADY SATISFIED in current code: the `assistantMsg` push + `saveSessionToFile` happen before
      the tool-execution `for` loop. The 1uwygz3dx "turn missing from JSON" case was an older build;
      no change needed. Verified during this refactor.

## Phase 7 — Stall watchdog fix + model-eviction stop  (STATUS: [x] done)
Root cause of the 47-min silent stall (session_xgwp0smf3, gemma4:26b): the CPU
"is it computing" probe sampled `% Processor Time` (an instantaneous rate) and
diffed two snapshots as if cumulative, so it only reported "computing" when CPU
*rose* between probes. On a memory-thrashing laptop the idle streak kept
resetting and never reached the kill count; only the 60-min turn budget could
have fired.
- [x] Replace the broken probe with cumulative `Get-Process .CPU` seconds
      sampled twice per probe → true work/sec; add a `conclusive` flag and drop
      the cross-tick `lastProbeCpuTicks` plumbing.
- [x] Add Ollama model-eviction stop via `/api/ps` (`ollama ps`): an empty model
      list for 2 consecutive 60s polls → `killRun("model ejected …")`.
      Independent of the quiet window, so evictions are caught in ~2 min.
      Knobs: `MODEL_EVICTION_WATCH`, `MODEL_PS_INTERVAL_MS`,
      `MODEL_GONE_CHECKS_TO_KILL`.
- [x] Surface idle + eviction count-downs as `status` events (no silent quiet).
- [x] Documented in README + `.env.example`.
- [x] `npm run typecheck` clean.
- [ ] Human: restart the dev server (tsx watch reloads on save), Force-Stop the
      hung run, and confirm on a real run that an eviction stops with "model
      ejected" and the idle count-down shows during a genuine quiet period.
